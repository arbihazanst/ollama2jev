# E4 — Numerical fidelity, cross-backend agreement and efficiency

**Current status (2026-10-17):** E4A complete from archived E1 diagnostics; E4B paired server experiment **not yet executed**. The E4A preverified snapshot is in `results/offline/e4a_verified_repository_snapshot.json`. Never label E4B as completed before the server outputs are generated.

## E4A: First-token probability integrity (no new inference)

Replay all 11 E1 JSONL files (11×231 decisions). For every recorded binary evaluation containing both lowercase `yes` and `no` log-probabilities, independently compute:

`q = exp(l_yes − max(l_yes,l_no)) / ( exp(l_yes − max) + exp(l_no − max) )`

Compare to archived `p_yes`. This checks the numerical adapter, **not** agreement with an independent full-vocabulary inference backend. It does not test differences due to prompt templates, quantization, or models' next-token logits. Run:

```bash
python experiments/04_backend_fidelity/scripts/audit_e1_logits.py
```

**Verified E1 snapshot:** 2,541 typed decisions, 9,327 recorded binary candidate attempts, 9,324 covered by both `yes` and `no`, three noncovered candidates in Granite 4.2 8B, maximum probability reconstruction discrepancy `2.776e−17`. These figures are independently recalculated from existing records; full per-model CSV/JSON regenerated by the audit script.

## E4B: Full-vocabulary logit comparator (new inference)

Use the **same LLM2Jev binary question compiler, message-level prompts, candidate order, and typed assembler** across two backends:

1. OllamaBackend: one token, temperature 0, thinking off, `top_logprobs=20`, with failure if either `yes` or `no` not covered.
2. TransformersBackend: prefill-only full next-token vocabulary logits, select **single-token** `yes` and `no` IDs, apply binary softmax; `batch_size=1`, thinking off.

By design, output is a *cross-stack comparison*, not a controlled exact-logit same-checkpoint evaluation unless the **weights, quantization, tokenizer, chat template, and model input token IDs have been independently matched**. HF FP/BF16 weights versus Ollama quantized GGUF differ; the two runtimes may apply different chat serialization/special tokens. Do not state a definitive "exact-logit fidelity" or estimate fine-tuning effects from this experiment alone.

Recommended pilot: Qwen3.5 0.8B, 15 JevBench tasks (five each Choice, Noul, Score), 3 repetitions. Main result: 54 reproducibly sampled balanced tasks (18 per type; seed 42), 3 repetitions; full 231 can follow, ideally also a second model if server resources allow. Report the *actual subset and repetition count* in the paper, never claim the 231-task analysis unless `--full` completed.

Metrics: typed accuracy per backend, paired prediction agreement, candidate-level MAE/RMSE/Pearson correlation, top-20 coverage, missing/error rate, per-decision p50/p95 and mean latency, and Brier/NLL/ECE on valid first-repetition predictions. Models are serially executed on the same server to avoid simultaneous GPU contention; execution order alternates by task and repetition. Initialization and warmup are outside timing. There is no claimed causal efficiency advantage without controlled hardware and verified model matching.

Run instructions are in `INSTALL_ON_SERVER.md` (at ZIP root).

## Scientific limitations

The exact conditional probability calculation does not depend on the other vocabulary logits **provided** both target token log-probabilities correspond to the intended token IDs and the identical token distribution. It is not an independent check of the underlying Ollama logit values. Reconstructed E1 diagnostics might be affected by conditional logit transformations, chat templates, quantization, or tokenization. Underlying dataset/public benchmark exposure must be acknowledged. E4B's HF checkpoint must match the intended *post-trained* (not Base) model.
